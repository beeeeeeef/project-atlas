> 所有数字都可以用文末的命令复现，不是手写的印象分。

## D1 · 抽取后端：为什么不用 GitNexus

**问题**：函数级调用边从哪来？

| 候选 | 结论 |
|---|---|
| 自己写 AST 解析 | 每种语言一套，维护成本不可接受 |
| GitNexus | tree-sitter + 知识图谱，但 **PolyForm 非商业许可**、230 MB、**没有整图 JSON 导出**、`analyze` 会往目标仓库写 hooks/AGENTS.md |
| **graphify** | Apache-2.0、`extract --code-only` 全离线、~8 s 出图、导出 NetworkX 格式、边带 `EXTRACTED/INFERRED` 置信度 |

**决定**：graphify 做抽取后端，且是**可选依赖**（缺失时降级到自研扫描）。

**代价（诚实记录）**：graphify 只导出「符号 + 关系」，**不导出类型字段**——数据页的字段要自己解析，这成了后续 100+ 行解析器的来源。

**证据**：httpx（78 个源文件）→ 1886 节点 / 3960 边，耗时 5.14 s。

## D2 · 模型只能解释，不能创造

**问题**：让模型直接生成架构图，会出现"看起来合理但源码里不存在"的模块。

**决定**：三层隔离
1. 节点/边来自抽取器；
2. 模型只能对**已存在的 id** 写 `role/why/risk`；
3. 未知 id 直接丢弃并计入 `meta.warnings`。

**证据**：对抗测试——故意写一份全假 id 的 insights：

```
✗ 没有关键链路（至少 1 条）
✗ 函数卡介绍覆盖率 0%（0/60），低于 50%
exit=2
```

**代价**：模型要逐卡写介绍，覆盖率不足会让构建失败（逼着补齐，而不是糊弄）。

---

## D3 · 布局与折行都放到构建期

**问题**：浏览器端用图库布局，产物会膨胀到几百 KB，且每次打开结果不稳定。

**候选**：cytoscape 435 KB / vis-network 653 KB / elkjs 1.57 MB / **dagre 283 KB（仅构建期）**

**决定**：构建期用 dagre 算坐标，产物只画 SVG；文字折行也在构建期算好写进 model。

**证据**：
- 产物 **175 KB**（含全部数据与渲染器）
- 首屏缩放 1.31–1.45，无需用户手动缩放
- 修掉一个真实缺陷：构建期与渲染期各算一套宽度 → 文字溢出 1–5.7 px；改为单一真相后 **0 溢出**

## D4 · 质量门：从"建议"变成"过不去就失败"

**问题**：一开始约束只写在 SKILL.md 里，属于建议；agent 可以只做一半就交付。

**决定**：把约束下沉到代码，默认严格。

| 门 | 判定 | 出处 |
|---|---|---|
| 概览 < 2 段 / 无入口 / 无链路 | 失败 | `check.mjs` |
| 函数卡介绍覆盖率 < 50% | 失败，并列出待补函数 | `check.mjs` |
| 空屏 / 节点重叠 / 单屏 > 45 | 失败 | `check.mjs` |
| 首屏缩放过低（< 0.45） | 失败 | `check.mjs` |
| 外链 / 占位符 / 网络调用 | 失败 | `verify.mjs` |
| 输入字段写错 | 失败，报 JSON 路径 | `validate.mjs` |

**证据**：拼错一个字段名（`layers` → `layer`）以前会静默降级（31 屏变 24 屏），现在：

```
✗ /layers  必填字段缺失
✗ /layer   未知字段（拼错了？或不该出现在这里）
```

**代价**：`--force` 是显式的逃生口，但产物会带黄条、不算交付。

## D5 · 增量更新

**问题**：每次重跑都要全量抽图，大仓库上很慢。

**先测量再设计**（httpx 78 文件）：

| 步骤 | 耗时 |
|---|---|
| graphify extract（全量） | 5.14 s |
| graphify update（改 1 文件） | 3.38 s |
| propose / build / verify | 0.09 / 0.09 / 0.07 s |

**发现**：抽图之外全流程只有 0.25 s，所以优化重点不是"抽得快"，而是"**能跳就跳**"。

**决定**：三层指纹（代码 / 输入 / 引擎资产）+ 四种动作：

| 场景 | 动作 |
|---|---|
| 代码与输入都没变 | 复用产物 |
| 只有 groups/insights/渲染资产变了 | 跳过抽图 |
| 代码变了 | graphify update |
| `--fresh` | 强制全量 |

**证据**（Algo-coach，136 个源文件，`tests/bench.mjs` 可复现）：

| 场景 | 耗时 | 相对首次 |
|---|---|---|
| 首次全量（冷缓存） | 4.29 s | 100% |
| 无变化再跑 | **0.11 s** | **2.6%** |
| 只改 insights | **0.42 s** | 9.8% |
| 改一处代码 | **1.58 s** | 36.8% |

**踩到的坑**：脏工作区里改文件不改变指纹（commit 没变），导致跳过该做的更新；而且我们自己的 `.atlas/` 会让仓库永远显示 dirty。
**修法**：脏时用「改动文件列表 + size + mtime」参与指纹，并忽略 `.atlas/`、`graphify-out/`。

**代价**：多了一份状态文件；状态与真实不符时可能复用旧产物——所以 `--fresh` 必须可靠（这一条也踩过：最初写成"强制更新"，已修正为"强制全量"）。

## D6 · 产物落点：不弄脏被分析的仓库

**问题**：graphify 默认把 `graphify-out/` 写进目标仓库。

**决定**：用 `GRAPHIFY_OUT` 重定向到 `<repo>/.atlas/`，产物也放这里；仓库不可写时回退当前目录。
**证据**：分析完 `demo/` 后，仓库里只剩 `src/app.py`；冒烟测试断言"不出现 graphify-out/"。

---

## D7 · 去掉了 `snippet` 字段

**问题**：类型解析时顺手存了每个类型的 12 行源码，但渲染器从未使用。

**证据**：产物 184.8 KB → **175.0 KB**（-9.8 KB）；同时消除"分析第三方仓库时产物内嵌别人源码"的风险。

**代价**：数据页暂不能再展示原文片段，只能给 `file:line` 锚点。

## 面试可以讲的三件事

1. **"为什么不用现成的图库/解析器"**：给结论 + 代价。用 graphify 省下 100+ 种语言的解析，代价是它不导出类型字段——于是自研 100 行针对性解析，并明确标注"不猜"。
2. **"怎么让 LLM 的输出可信"**：不是 prompt 里写"不要编"，而是**结构上不能编**——节点来自抽取器，模型只能填已存在的 id；写错就丢，覆盖率不足就构建失败。
3. **"怎么做性能优化"**：先测量再动手。数据表明抽图占 95% 时间，于是优化方向定为"跳过"而不是"算得更快"，最终无变化场景从 4.29 s 降到 0.11 s。

---

## 明确放弃的东西（也是取舍）

- **时序图**：静态分析拿不到运行时数据，只能靠模型猜 → 不做。
- **跨仓库地图**：价值高但成本高，留到 v2。
- **字段级跨端对齐**：只做同名类型连线，不做字段映射（避免幻觉）。
- **自动改用户的 `.gitignore`**：只打印建议，不碰用户文件。
